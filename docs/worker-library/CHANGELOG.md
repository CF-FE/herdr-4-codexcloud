# Worker 与角色库变更记录

## 2026-11-10：角色库 1.0.2

- 共同合同从 1.0.0 升至 1.0.1，所有现有及后续新增角色继承组织协作技能的 GitHub 组织规范，派发时交接执行端可读的固定引用或适用条款。角色正文与 Worker 模板版本不变，初始来源清单保留。
- 新准备稿携带共同引用；在途角色沿原任务的接单、恢复或交接点读取，不自动重派或热换角色。结构、引用及离线生成稿检查不代表各宿主已加载新版。

## 2026-11-03：角色库 1.0.1

- 云端Dot 的组织导航更名为 `cloud_dot_organization_lead`，定义从 1.0.0 升至 1.0.1，与 Mac 项目协调员区分。历史来源 ID 仍可查询同一不可派发的导航项。Worker 库、任命、运行身份及在途任务均无变化。
- 初始来源清单的两条中文改编说明采用统一称谓；固定来源、路径、导入版本、原件及初版接收摘要均保留。

## 2026-11-02：两个库的 1.0.0 初版

- Worker 库：7 个模板、9 个显式后端，覆盖 Cloud、Mac Codex／Kimi、Win OMP／Hermes／Kimi 与无模型命令任务。能力为候选声明，证据及观察归属分列，未登记实时占用或创建运行实例。
- 角色库：按源维护方正式 14 文件清单接收专业库 1.1.1 的定义闭包，固定来源 `CF-FE/mymcp-4-codexcloud@02e6ca4c1cb201904abd2ef2f107f6dce957e051`。原 11 个 ID 保留，两个组织导航不可派发；本仓新增 `software_implementation`、`artifact_processing`，共 13 定义、11 专业候选。
- 本地适配：修复组织相对链接，移除旧平台 Save／模型排序的运行适用性；组织任命、项目写权与模型选择按当前任务绑定，项目硬要求保留。初始原件与接收摘要见 [source-manifest.json](source-manifest.json)，两库从各自 1.0.0 开始独立维护。
- 接口：新增离线 `check / list / roles / role / select / prepare`；按角色与声明能力筛选，组装有版本和摘要的请求稿。没有自动模型选择、回退、部署、任务提交或 Worker 创建。
- 验证范围：27 项测试（原 11＋新增 16）、真库／结构检查、工作区引用和来源闭包通过；真实模型、Herdr 主线、信箱各客户端及业务验收不因入库升级。Win Kimi 代理入口的精确模型别名未由交接材料给出，参数稿保留显式待绑定项，不从 provider 名推定。

后续条目须注明改变的对象、前后版本、原因、采用点、验证与未验范围；不重写此次首次来源摘要或静默更新在途任务。
