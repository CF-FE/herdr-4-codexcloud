# ADR-002　共享项目记忆与非阻塞的云端接入

2026-11-05 · 已采纳，待实施验收。公子采纳本轮方案，明确复用 `vps-vultr` 与已组网的 VPS ↔ win-work EasyTier，将云端Dot、Codex Cloud 纳入 Hindsight；现有 Hindsight 会话实施、连通性会话协助、原审核窗口验收。[实施文档](../hindsight-memory-integration.md)拥有交付与验证要求。

## 问题与依据

仓库适合正式规则和工作流，不适合让每个执行者逐条提交接手经验；每机记忆又难跨 Harness 承接。所有执行依赖远端召回会重新引入弱连接等待，“客户端已配置”也不代表原生任务能用。现有服务与自启已有实施侧报告，本轮复用，公网和云端采用分别取证。

## 决定

- 稳定项目身份映射一个 bank，同项目跨机器、跨角色共享。项目连接固定bank或跨项目入口显式选bank，缺项目不写默认库。
- 仓库维护正式规范、工作流、设计决定及短记忆入口；Hindsight保存经验、背景与引用。不两份手工维护、不双向自动改写。任务、检查点、GitHub和信箱继续拥有各自状态。
- 云端Dot写确认后的需求与决定，Worker直接贡献经验，不逐条审批；正式规范和验收沿原责任，云端Dot不任业务验收者。
- 公网经 `vps-vultr` 独立 HTTPS MCP 入口与既有 EasyTier／SSH 到 Win 代理；VPS 做必要的传输适配，不复制记忆库。按公子指定，VPS 入口在 `create-network-sh/fastmcp/` 维护，本仓拥有共享合同与本地接入。Mac 走既有局域网 SSH，云端不为此装 VPN。
- 所有 Agent 首选 MCP，云端Dot与 Codex Cloud 首选 VPS HTTPS MCP。公子后续明确允许 Hindsight API 兜底及较长超时／重试，覆盖此前只许 MCP 的限制；兜底保持同项目、同授权与原服务，记录真实采用方式，不以 API 成功冒充 MCP 已验。
- 同一调用使用一个截止时间和有限重试预算，避免层层倍增；API 可绕过 MCP 协议／会话故障，不能绕过两条路径共同依赖的 EasyTier 断网。先做这些小改动，不新增 VPS 缓存／后台队列系统。
- 弱连接优化只针对 `vps-vultr ↔ win-work`，先分析两端 EasyTier 日志再确定网络改动；Mac ↔ Win 局域网路径保持现状。
- 接手／恢复／缺背景时召回，重要决定和单元结束时沉淀。必要上下文随原任务保存；不可达时继续确定步骤，只让缺依据的决定点等待，写失败沿原任务待补。
- 保留ADR-001的项目自有工作流及版本化记忆入口。入口摘要只固定本地文件；动态召回采用内容在原任务记录，不伪称bank快照，不自动改在途决定。

## 取舍与复议

共享bank减少重复交接，代价是在线召回依赖Win与网络；用任务输入保留必要背景，不扩为数据库同步或新的高可用平台。按节点沉淀减少每轮全量保留聊天的噪声、提取成本和延迟。

现阶段不建双活库、专职记忆协调员、GPU调度器、每轮强制reflect或事件唤醒；真实用量或离线需求变化后再决定。云端接入不改变Herdr宿主与业务责任链。

本记录补充[ADR-001](001-project-owned-workflows.md)的共享记忆方式；其工作流所有权、程序执行／模型决策及验收分工仍有效。
