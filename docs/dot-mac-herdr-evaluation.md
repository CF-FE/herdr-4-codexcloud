## 2. 执行范围与预算

- 仅在现有有效授权内执行；已明确授权的常规步骤直接推进，缺失权限只停止依赖分支并报告。
- 测试文本回合合计最多 **2 个：Codex 1 个、Kimi 1 个**。不补问、不重发 prompt、不换模型、不让 Agent 再派子任务；如只能完成一侧，如实报告。
- 不新增业务文件写入，不编辑仓库／用户工程；允许保存本次脱敏报告与必要原始证据到已有获准私密落点。Herdr／CLI 正常维护自身会话状态不作为业务文件成果。
- 总评估窗口最多 15 分钟；原生任务／状态／列表／结果查询合计最多 20 次，本地 help／version 调用另计。每个模型回合观察最多 120 秒；不连续后台轮询，预算到达即收敛为已知结果或 UNKNOWN。
- 记录原生接口实际调用次数、调用内命令次数、显式模型回合数；内部请求／用量不可读时记 UNKNOWN，不能把两个文本回合写成仅两次 API 请求或零费用。
- 不为本次测试登录、安装、启停系统服务、修改认证／权限／网络／睡眠设置，不制造断网、合盖、重启或恢复故障，不创建后台监控。
- VPS、Win、Cloud VPN、Lody、真实项目、多项目负载及生产迁移均不纳入本次验证。

## 3. 入口与目标绑定

1. Dot 先用自身实际提供的原生入口定位既有 Mac 本地任务，核当前身份、设备、工作目录和任务允许范围；不得把其他会话的工具回执冒称自己调用。
2. 确认原任务没有未决执行或冲突写者；若曾投递超时，先查原请求，不先投递新的操作。
3. 在 Mac 仅先读取目标版帮助与版本，例如 herdr --version、herdr --help、herdr session --help、herdr agent --help；具体创建、定向与读取参数按本机帮助核实，不套用 hc 命令。
4. 为本次评估新建独立命名 session，标签关联 test_id；保存原生 session／workspace／pane／Agent ID，后续所有操作显式定向。只有公子已明确移交且已核无未决工作的专用测试 session 才可复用。
5. 准备侧检测 workspace／session 已按原 ID 清理，默认 session 保留，旧测试 ID 不可复用；已有双 Agent 识别结果只作基线。未明确移交时不向其注入消息，更不操作公子既有业务 pane。不要关闭 Local／默认 session 来实现清理。

外部 Dot／Mac 控制可以沿已授权的原生任务执行系统 herdr CLI；安装 Herdr skill 不授予这种外部权限。Herdr 内部 Agent 只有处于真实管理窗格、实际具备 HERDR_ENV=1 等适用条件时，才使用相应技能；不得手工伪造该变量或 pane 身份。

E1 可以使用 shell 的 printf，格式字符串与 nonce 分开传入，使最终整行输出不原样出现在输入命令中；不得仅搜索输入行是否出现 nonce。

E2／E3 的建议请求是：本回合禁止调用工具、联网、写文件或委派子任务；给出三个随机短片段组成的 nonce，请把片段顺序倒置，仅返回一个 ACK 行。预期完整 ACK 不写进 prompt，由测试方独立计算后核对，排除终端回显。

两侧使用不同 nonce，并记录各自输入提交、受理、生成和回读时点；不要求两侧并发。若已有模型输出无法和本次请求区分，结论为 UNKNOWN，不能再次询问来修补证据。

按原生回合记录核工具调用是否为 0，不能只凭 prompt 中的禁止说明认定没有工具效果；不可取得时记 UNKNOWN。

完成通知与原任务终态若有先后差异，分别记实。若原本地任务已 completed，后续清理查询须使用原生入口实际支持且已获准的续接／只读机制，记录其与原任务的关系。若续接使原任务重新活动，清理结束后再回读最终状态，不沿用旧 completed 冒称本轮全部完成。

## 5. 必须保留的证据与停止规则

每步至少关联以下字段；公开报告用稳定别名，实际私密 ID 与映射保存在获准原始证据中：

```text
test_id / step_id / request_attempt / observer / actual_entry

nonce / expected-result digest / observed-result digest or short safe result
requested_at / accepted_at / started_at / finished_at / read_at / timezone
outer tool status / actual command exit code / original task state
acceptance / execution / readback / notification / cleanup status
raw_evidence_reference / redacted_artifact_reference / next_owner
```

- 首次受理不明、timeout 或原生状态不一致时，保留原请求引用，在剩余查询预算内查原执行、pane 与结果；不重投、不新建替代任务或换控制入口。
- 明确拒绝、要求登录／计费开通、目标身份冲突、发现既有工作或发生越界动作时，停止受影响步骤；其他已具备条件的只读收尾可继续。
- 外层工具返回成功不代表远端执行成功；idle／interactive_ready／completed 分别只证明其原生含义，不替代输出核对。
- 不为取得失败样本重复提交；不要求关机／断网注入。小样本成功不称长期稳定、SLA、生产可用或任意规模协作通过。
- 如无法安全清理未决 Agent，保留其引用、当前状态和承接人，停止继续准入；不能为清理而强制关闭未知或非本次资源。

| 状态 | 使用条件 |

| M3 Herdr 承接 | Mac 读取获准任务，绑定本地目标与唯一写者，沿现有 Herdr 操作取证，再发布并由接收者读回结果 | 常驻桥只收件／补传，Herdr 执行 handler 未实现；仍需原执行者或明确接线。真实模型回合受对应任务已定预算约束，不重复测试已知结果来凑证据 |

Cloud 如后续在获准任务内参与 M2，应按独立 job／事件／结果引用记录 Cloud → 信箱 → 指定接收者及反向读取，不能把 Dot 的回执改名为 Cloud 已调用。公网服务可达与 Cloud 命令网络、托管 MCP 工具分别核验；仅在采用命令客户端时才按该环境的实际网络配置核准目标域名与认证，不默认开放全部互联网或复制 Mac 的认证缓存。[Cloud 服务访问](https://learn.chatgpt.com/docs/environments/cloud-environments#connect-to-services)、[托管工具与命令网络](https://learn.chatgpt.com/docs/enterprise/agent-security#execution-controls-executor)

信箱及 Mac 桥唯一维护仓为 [CF-FE/task-mailbox-mcp](https://github.com/CF-FE/task-mailbox-mcp)，个人整合仓只留历史来源；数据契约以其[服务 SPEC](https://github.com/CF-FE/task-mailbox-mcp/blob/main/SPEC.md)为准：同 ID 同内容查原记录，冲突拒绝；结果状态为调用方报告，取消仅请求，读确认不代替业务验收或写权交还。模型／原件和大产物保留原宿主或获准 Space／Git 落点，只在信箱传小结果及可核引用。当前单用户认证不因 `sender/recipient` 标签而产生多租户隔离。

本次文档修订不执行上述步骤、不创建 Cloud 任务、登录或模型回合；原实施会话继续负责其已获准的部署／接入。本仓只保存方案和分层状态，不复制服务代码、私密配置或运行数据库。
