# 工作流改进治理

版本 1.0.0 · 2026-11-13。

从阻塞处置和阶段或结束复盘识别工作流改进，沿原任务取证，交实际维护者决定和办理。适用对象包括项目流程、跨项目复用的流程和编排器。具体审批、执行、恢复和验收沿现有协议办理。

## 从原任务分诊

1. **阻塞处置。** 收到阻塞回执或巡检发现阻塞时，云端Dot核原任务、现象和影响，按现有规则做有界只读排查，必要时沿原协调链限定派查。记录已核事实、候选原因、反证和未验项。处置当前阻塞与改进以后做法可以各自推进。批准仍有效、范围不变且前提齐备时，沿原执行者、原意图和检查点接续，无需重批或等提案发布。新增修复或推进按 G8 规则提交公子审查批准。[阻塞处置](coordination-policy.md#g8-阻塞主动排查与执行审批)
2. **阶段或结束复盘。** 在原任务的阶段回执或结束记录中核对预期、实际结果、等待与返工原因、失败／取消／部分完成的实际效果及遗留项。由原负责人或协调员沿现有责任链处理发现。历史回放引用当时的版本与回执，保留原单的结论与结案状态。后续改进须明确适用范围。[验收与回看](coordination-policy.md#6-验收反例与回看)

两类入口都先在原单记录触发事实、观察时间、受影响的工作流或组件版本、原动作及证据引用。按原任务、受影响对象和拟解决的缺口查重。同一缺口已有主提案时补证据与原单关联。执行效果 `UNKNOWN` 时由原派发者沿原引用对账。

小问题在原记录简述原因、证据、处置和结果即可。可复用经验按现有规则附原任务、来源和观察时间沉淀到 Hindsight，正式规范继续由所属仓版本化维护。只需处置原单或沉淀经验时，可在原单结束分诊。拟对以后做法作一项独立变更时，用[提案模板](templates/workflow-improvement-proposal.md)说明改动及其验证方式。

## 按修改对象找维护者

| 修改对象 | 主提案及交付归属 |
| --- | --- |
| 项目级工作流 | 具体项目的步骤、规则、质量口径、输入输出或交接。由现任项目负责人在该项目主仓维护。 |
| 通用级工作流 | 跨项目适用的流程规则、职责与决定／交接合同，以及通用生成器、流程模板。交拥有相应合同或工具的维护仓，例如通用审批流程与通用生成器归 Herdr 协调仓。 |
| 编排器 | 工作流实际运行的调度、检查点与恢复、定向联络、原生路由等机制。交拥有相应实现或接口的维护仓，例如协调跟进与定向联络归 Herdr 协调仓，Task Mailbox／Mac 桥的传输适配归服务仓。 |

跨仓时，由协调员按提案的主要改动确认主维护仓，复用一个主提案，各仓只关联自己需要交付的部分。项目实施与验收沿各自原任务办理，涉及在途任务时由负责人说明适用版本和切换点。[项目维护边界](coordination-policy.md#项目主仓与项目级规范) · [组件维护归属](architecture.md#唯一维护位置)

## 从提案到验证

1. **整理与审查。** 云端Dot汇总来源、影响、方案及推荐。重大改动比较可行替代方案与沿用现状，说明收益、证据、代价和回退。小改动用简短依据。主提案保留范围版本、原任务和证据引用，候选标明待决定。需要 GitHub Issue 展示时优先复用已有条目，先核目标仓、可见性和实际发布授权，由获授权记录者发布可公开的方案摘要及原审批引用。私有证据留在受控原处，决定从原审批入口接回。[审批路由](approval-workflow.md#4-路由投递与答复接回) · [GitHub 记录通道](project-coordinator.md#nonblocking-contact)
2. **决定与承接。** 有权者在职责范围内决定。新增授权和变更公子已定范围由云端Dot提请公子决定，已有明确、有效、适用的批准直接关联原证据。范围变化时注明差异并核原批准。可独立处理的新增授权缺口单独提报；实质变化影响原批准的前提、依赖或整体风险时，重核受影响的整体范围并据此提报。承接时沿现有岗位绑定明确负责人、执行者、验收者、交期和回报位置。云端Dot可指派验收者，由原单指定的验收者作业务决定。新交付沿获准路由办理并关联原单。恢复在途动作时沿原检查点接续。[默认分工](coordination-policy.md#1-默认分工与取舍) · [审批与接续](approval-workflow.md)
3. **分项取证。** 批准记录有权者、范围版本与决定来源。实施记录提交或产物、检查方法和结果。部署和规则读取各记实际版本、目标宿主或会话、读回范围与时间。真实采用关联实际任务及所用版本。业务验收记录指定验收者、确切产物及其决定。复盘收益时选与原问题相关、可同口径观察的指标。缺项写明未取得或不适用及其理由。[逐层验证](pilot.md#逐层验证)

## 退出与历史回放

- **暂缓。** 沿原单留原因、当前承接人、恢复条件和复查点。到期处理沿现有跟进或审批约定；已授权且就绪的独立工作继续。
- **不采用。** 留实际决定、适用范围和理由，结束提案跟进。可复用的发现仍可带来源沉淀。
- **失败、取消或部分完成。** 保存已完成项、已知效果与未决项，明确后续责任。按原协议对账并处理获准的回退或恢复，原验收者按实际结果决定相应范围是否放行。[审批异常出口](approval-workflow.md#5-等待恢复与异常出口) · [取消与写权](coordination-policy.md#5-幂等异常与移交)

使用[六组提案模板](templates/workflow-improvement-proposal.md)，对照[已批准恢复单](examples/workflow-improvement/approved-recovery.md)与[凡人离线 QA](examples/workflow-improvement/fanren-offline-qa.md)的历史回放。回放核对证据能支持的结论及边界。当前交付为规范、模板和历史证据回放，实际运行与采用沿后续获准任务取证。
